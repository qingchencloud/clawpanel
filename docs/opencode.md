# OpenCode 使用指南

ClawPanel 将 OpenCode 的安装配置和实际操作分为两个页面；模型渠道可与其他引擎共用，运行时独立于 OpenClaw Gateway。

## 开始使用

1. 左侧引擎切换器选择 **OpenCode**，进入「运行与配置」。
2. 完成受管安装。当前仓库的初始安装基线为 `opencode-ai@1.19.2`，以配置页显示的目标版本为准，不代表上游最新版本。
3. 在「通用 → 模型渠道」保存地址、Key、模型，点击「同步到 OpenCode」，按需设置默认模型。
4. 启动服务，通过左侧「工作台」进入内嵌 OpenCode Web 界面，添加项目、创建会话并选择模型。

当前同步转换支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages，以及 Ollama 的 OpenAI 兼容 `/v1`。Google Generative AI、OAuth 和结构化 SecretRef 不在此同步路径中。配置回读后仍需实际对话验证。

## 网络和目录

- 默认回环端口 **4096**，可在配置页修改；端口被其他进程占用时先换端口，不自动终止外部服务。
- Web 模式通过面板认证后的代理内嵌，不必额外向外网开放 4096。工作台使用 OpenCode 自身界面，不是 OpenClaw 的实时聊天页。
- 受管运行时、配置和凭据位于当前 OpenClaw 配置根目录的 `clawpanel/opencode/`；密钥写入独立文件，不直接写在 Provider 配置中。
- Web 的项目路径属于面板服务器；Docker 中项目须单独挂载。共享登录与工作目录不构成多用户代码执行隔离。

## Web 工作台存储与刷新

- 原生页面保留自己的路由。面板代理使用短期能力地址，不向浏览器暴露内核密码；同源代理仍使用 opaque sandbox，没有授予 `allow-same-origin`。
- 仅 OpenCode 的偏好和 `opencode-drafts` 草稿通过隔离存储桥保存；不读取面板 Cookie、其他引擎或任意数据库。草稿的文本与附件使用原生 IndexedDB 事务，支持原子提交和中止。
- 偏好限额为 2M 个 UTF-16 代码单元，草稿值限 16MiB、总计 32MiB；浏览器实际配额不足时会显示保存失败。偏好桥的持久化确认是异步的，不等同于原生同步 WebStorage 的全部语义。
- 刷新整个面板后，可点击原生工作台保留的会话标签重新打开历史和未发送草稿。服务器会话保存在受管目录；浏览器偏好和草稿仅属于当前浏览器来源，清理浏览器数据或更换域名/端口前需自行保存未发送内容。

## 在线更新与卸载

- **检查更新 / 在线更新**仅针对 ClawPanel 受管安装；读取 npm 发布版本，安装到 staging，核验后切换，切换失败恢复原运行时。
- 更新运行中的受管服务会停机并尝试重新启动；若重启失败，配置页会报告错误，需检查日志。上游有新版本不等于所有新功能都经过面板验收。
- **卸载**停止受管进程并删除受管运行时，保留 `home/` 下的配置、凭据、项目及运行数据。卸载不等于彻底清除敏感数据，清理前先备份并确认目录。
- 外部启动的实例不按受管进程处理；面板会限制相应停止、更新或卸载操作。

## 排查

模型没出现先检查目标同步和默认模型，再刷新/重新加载工作台。启动失败查看配置页错误、受管日志及端口占用；更新后的网络调用失败查看 Base URL、Key、模型 ID 和实际 Provider 协议。

另见 [多引擎与模型渠道](engines-and-models.md)、[Docker 部署](docker-deploy.md)。

冷启动草稿事务按读写冲突有界排队，最多 64 个等待事务；父桥仍最多 8 个活跃事务，等待与执行均保留超时及数据配额。该桥只实现当前原生页面使用的窄接口，不承诺完整 IndexedDB/WebStorage 兼容。
