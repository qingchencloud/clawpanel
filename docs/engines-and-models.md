# 多引擎与模型渠道

## 选择适合的引擎

| 引擎 | 面板入口与用途 | 与 OpenClaw Gateway 的关系 |
|---|---|---|
| OpenClaw | 仪表盘、实时聊天、Agent、消息渠道、记忆及自动化 | 依赖 OpenClaw Gateway |
| Hermes Agent | 独立设置向导、聊天、记忆、工具与消息渠道 | 使用 Hermes 自身运行环境 |
| DeepSeek Harness（DSH） | 「运行与配置」安装启停；「工作台」内嵌 DSH Web 界面 | 独立运行，内嵌服务监听回环地址 |
| OpenCode | 「运行与配置」安装、更新与启停；「工作台」内嵌 OpenCode Web 界面 | 独立运行，内嵌服务监听回环地址 |
| Pi（实验版） | 「运行与配置」安装和授权；「工作台」使用面板原生 RPC 聊天 | 独立运行，不需要 OpenClaw Gateway |

侧栏中的「心甜Claw」是产品介绍与下载入口，不是第六个受管本地运行时。引擎切换不会自动安装所有引擎，也不会把 OpenClaw 的 Agent、消息渠道、记忆和 Skills 迁移给其他引擎。

### 运行环境

- 推荐使用完整 Node.js **24.16.0+（24.x）** 和 npm，同时满足当前仓库 OpenClaw 官方推荐版本的运行要求。仅能启动面板的旧版 Node 不等于能启动所有引擎。
- OpenClaw 的具体 Node 约束按安装版本检测；官方版/汉化版推荐版本以随包的 `openclaw-version-policy.json` 为准。新安装默认选择官方稳定版，汉化版仍可显式选择。
- Pi 当前固定验收版本为 `@earendil-works/pi-coding-agent@1.1.0`，要求 Node.js >=22.19.0 和 npm。检查上游更新不代表自动升级到尚未验收的版本。
- Hermes 还需要自身的 Python 环境及依赖，以它的设置向导为准。Docker 镜像预装 OpenClaw 不代表已安装 Hermes、DSH、OpenCode 和 Pi。

## 一处保存，按目标同步

「通用 → 模型渠道」是共享配置入口；OpenClaw 的「模型配置」仍是 OpenClaw 专属入口。

1. 新建渠道，填写 **Base URL、API 类型、API Key**，拉取或手动添加模型 ID。
2. 按实际模型及后端服务能力设置上下文窗口、输出上限和默认模型；这些数值是配置，不会扩大模型服务器实际加载的上下文容量。
3. 保存渠道。保存只更新渠道库，**不会自动覆盖所有引擎**。
4. 点击对应的「同步到 OpenClaw / Hermes / DeepSeek Harness / OpenCode / Pi」，按提示决定是否切换默认模型。
5. 返回该引擎的聊天页或工作台，选择模型，发出一条测试消息并检查完整回复。

编辑已同步渠道后，需要再次同步到目标。各目标绑定状态分开显示；从已有配置导入也不会自动同步给其他引擎。晴辰助手是独立同步目标，不计入受管引擎数量。

### API 类型不是通用通行证

以下为当前面板**配置转换**范围；真实调用仍受引擎版本、Provider 和模型限制。

| 渠道 API 类型 | Hermes | DSH | OpenCode | Pi |
|---|---|---|---|---|
| OpenAI Chat Completions | 支持 | 支持 | 支持 | 支持 |
| OpenAI Responses | 当前无此同步转换 | 支持 | 支持 | 支持 |
| Anthropic Messages | 支持 | 支持 | 支持 | 支持 |
| Google Generative AI | Gemini Provider 转换 | 当前无此同步转换 | 当前无此同步转换 | 支持 |
| Ollama | 当前无此同步转换；可建立 OpenAI 兼容渠道 | 转为 `/v1` | 转为 `/v1` | 转为 `/v1` |

OpenClaw 按自己的模型 API 类型和版本能力处理。结构化 SecretRef、OAuth 或云 SDK 认证不等于普通 API Key；各引擎同步按钮会按支持情况限制，必要时使用该引擎的原生配置流程。

## Web 版的「本地」是服务端

- 模型测试、CLI 安装、工作目录和文件工具在**运行面板的机器**执行，不在访问它的浏览器电脑上执行。
- 浏览器填写 `127.0.0.1`，模型调用连接的是面板服务器/容器自己的回环地址。LM Studio 在另一台机器时，填写该机器可达的内网地址，并检查服务监听和防火墙。
- Docker 中选择工作目录前先挂载项目，例如 `/workspace`；容器内路径不是宿主机原路径。只挂载需要的目录，避免挂载整个主目录或 Docker socket。
- Web 登录不是操作系统沙箱或多用户执行隔离。尤其是 Pi 的命令权限，逐次审批通过后仍使用面板进程所属账号的系统权限。

## 更新、卸载与备份

面板升级与引擎升级是两件事。先查看目标引擎的「运行与配置」或版本管理页；各引擎的固定验收版本、检查更新和在线升级策略不同。

Pi 和 OpenCode 的卸载只移除各自受管运行时，保留配置与历史，详情见各自指南。不要将这一规则套用到其他引擎或手动删除整个 `~/.openclaw`。

备份至少包括：当前配置根目录、各引擎自己的数据目录，以及额外挂载的项目目录。Web 升级使用完整 `web-x.y.z.zip` 或重新构建镜像；桌面前端热更新包不包含完整服务端。

## 常见排查路径

| 现象 | 优先检查 |
|---|---|
| 渠道保存后工作台没有模型 | 是否点击目标同步、是否支持该 API 类型、是否有已保存 Key；刷新工作台模型列表 |
| 显示已同步但对话失败 | 引擎日志、模型 ID、服务端到 Base URL 的连通性、认证方式；已同步只说明配置写入核验 |
| 本地模型上下文上限不生效 | 同步的模型上限、默认模型是否正确，以及 LM Studio/Ollama 实际加载参数 |
| Gateway 在运行，实时聊天却一直重连 | 代理 WebSocket 升级、Token/配对、前后端版本；进程状态与握手成功分开判断 |
| 升级后有页面或 API 异常 | `GET /__api/health` 的前后端版本、完整包是否同步、服务是否重启、浏览器缓存 |
| Pi 无响应或等待确认 | 当前会话审批、后台会话提示、运行日志；断线恢复不自动重复发送任务 |

提交反馈时附面板/引擎版本、部署方式、具体页面、错误文字及脱敏日志。不要附 API Key、Token、Cookie 或完整凭据文件。
